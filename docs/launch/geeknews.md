## 링크

## 본문

지난 1년 동안 개인 AI 에이전트 6~7개를 직접 만든 인프라에서 돌려 왔습니다.
AI 뉴스 요약, 미국 주식 + 한국 ETF 트래커, GitHub 피드 워처 같은 좁은 일들입니다.
전체 비용은 LLM 청구서 기준으로 **월 $1.26 정도**. 비결은 모델을 작게 쓰고, 매 실행
비용 / 일간 / 월간 한도를 디스크에 박아둔 것입니다.

가장 오래 걸린 부분은 에이전트 자체가 아니라 그 옆에 두는 런타임이었습니다.
스킵할 때마다 사고가 났던 세 가지:

1. **재시작에도 살아남는 비용 한도**. "하룻밤에 $47,000 청구" 사례는 이미 업계
   레퍼런스. 일간/월간 카운터를 디스크에 박아 두는 게 핵심입니다.
2. **에이전트가 죽었을 때 진짜로 살려내는 와치독**. cron만으로는 새벽 3시 LLM
   90초 블립을 회복 못 합니다.
3. **같은 대시보드에서 누르는 비상 정지**. 사고 났을 때 터미널 세 개 띄울 시간이
   없습니다.

Flux는 그 세 가지를 중심에 두고 만든 런타임입니다.

- **Safety Shield**: 실행당/일간/월간 하드 캡, 디스크 영속화, 80%·95% 임계 경고,
  `flux halt` 비상 정지
- **Watchdog**: PID + 하트비트 + 연속 실패를 보는 별도 프로세스. exponential
  backoff(30초 → 30분 천장)로 재시작
- **멀티테넌트 웹 UI**: GitHub OAuth, 유저별 격리(cross-tenant 응답은 403이 아니라
  404로 — 존재 자체를 노출하지 않습니다), 에이전트 상세 페이지에 WebSocket 라이브 로그
- **BYOK**: LLM 키는 DB에 절대 저장하지 않습니다
- 113개 테스트, Apache-2.0, `pip install flux-agent[api]`

호스팅 버전은 아직 없습니다. 오늘은 셀프호스트 전용입니다
(`docker compose up postgres` + `flux serve` + `pnpm dev` 세 줄이면 시작).
호스팅은 OSS 에디션을 충분히 굴려 본 다음 단계에서 고민하려 합니다.
